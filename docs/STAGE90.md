# STAGE 90 — 구조와 새 단계 만들기

9단계 × (일반 9 + 보스 1) = 90 스테이지 서바이벌 퀴즈입니다. 혼자 플레이하며, 진행 상황은 브라우저 localStorage에 저장됩니다. 이어하기와 초기화를 지원합니다.

## 게임 규칙 (사용자가 정한 원문 요약 — 바꾸지 말 것)
- **Normal Stage** 9개(행운·수리·타자·암호·눈치·두뇌·반응·순서·지식)는 단계가 시작될 때 **플레이어가 순서를 정합니다**. 남은 순서는 중간에 다시 바꿀 수 있습니다.
- 미션마다 브리핑 화면(유형, Lv, 설명, 규칙 칩)을 보여 줍니다. 여기서 **도전 / 패스 / 아이템 선언**을 고르면 3·2·1 카운트다운 뒤 문제가 공개됩니다.
- 성공 **+1 Level**, 실패 **−1 Level**.
- **패스**: Level 변화 없음. 단계당 최대 2회이고, 도전 전에만 쓸 수 있습니다.
- **Boss**: 항상 마지막. 패스·아이템 불가. 성공 +1 Level +1 HP + 스톤, 실패 −1 Level −1 HP.
- **HP**: 시작 3, 최대 5. 단계 결산 때 그 단계의 Level 합이 음수면 −1 HP. HP 0이면 퇴장.
- **아이템**:
  - 🛡️ 방패 ×3: 도전 전에 선언하면, 실패해도 패스로 처리됩니다.
  - 🧪 HP 물약 ×1: HP가 0이 되는 순간 자동으로 쓰입니다. 직접 써도 됩니다.
  - 🔴 리얼리티 스톤 ×1: 문제를 미리 보고 30초 안에 도전할지 패스할지 결정합니다. 시간이 지나면 자동으로 도전합니다.
- **보스 보상 스톤** (단계 → 스톤):

  | 단계 | 스톤 | 효과 | 상태 |
  |---|---|---|---|
  | 1 | 🔷 스페이스 | 실패 결과 직후에 쓰면 실패를 무효로 하고 패스 처리 | ✅ 구현 |
  | 2 | 🟡 마인드 | 일반 미션 도전 전에 선언하면, 성공 보상이 +1 Level 대신 +1 HP | ✅ 구현 |
  | 3 | 🟣 파워 | 도전 전에 선언하면 그 미션의 제한 시간이 무제한 (시간 있는 일반 미션만) | ✅ 구현 |
  | 4 | 🟢 타임 | 실패하면 같은 문제로 최대 2번 재도전 | ⬜ 설명만 있음 → **4단계 만들 때 구현** |
  | 5 | 🟠 소울 | 언제든 HP 1 ↔ Level 2 교환 | ⬜ 설명만 있음 |
  | 6 | ⏳ 크로노스의 눈 | Level 및 순위 2명 확인, 7단계 보스에 실패해도 아이템 획득 | ⬜ 설명만 있음 (1인용이라 순위 부분은 해석 필요) |
  | 7 | ☀️ 카이사르의 달력 | 특정 테마 도전 전에 쓰고 성공하면, 그 테마의 1~6단계 결과를 모두 패스로 바꿈 | ⬜ 설명만 있음 |

  - 각 단계 이미지 묶음 끝의 "보스 스테이지 성공 보상" 카드가 원문입니다. 새 단계를 만들 때 그 카드 문구로 `ITEMS[key].desc`를 맞추고 효과를 구현합니다.
- 리로드 방지: 미션 도중 페이지를 떠나면(`S.cur.live`) 다음 접속 때 **실패**로 처리합니다.

## 파일
```
s90/index.html   화면, CSS, script 순서: stage1.js, stage2.js, stage3.js, …, s90.js (엔진이 마지막)
s90/s90.js       엔진 (상태, HUD, 화면 라우터, 미션 종류별 화면·로직, 판정, 아이템)
s90/stageN.js    (window.S90_STAGES = window.S90_STAGES || {})[N] = { no, bossReward, missions: { 행운: {...}, …, 보스: {...} } }
s90/assets/      이미지 (예: s3-boss.png)
```
- 저장: localStorage 키는 `s90-save-v1`입니다. 메인 메뉴(`/index.html`)도 이 키를 읽어 "N단계 · Level · HP"를 표시합니다.
- 다음 단계 파일이 없으면 단계 결산 뒤 "준비 중" 화면이 나옵니다. 진행은 그대로 보존됩니다.

## 미션 데이터 공통 필드
```js
{ kind, lv, name?, time?, once?, brief, rules: ['제한 시간 10초', '1회 오답 시 실패', …], …kind별 필드 }
```
- `brief`: 브리핑 설명 한두 문장입니다. 문제 자체는 숨기고 형식만 설명합니다.
- `rules`: 칩으로 보여 줍니다. 첫 항목은 순서 정하기 화면에도 나옵니다. 카드에 적힌 제한 시간과 실패 조건을 그대로 옮깁니다.
- `time`: 초 단위입니다. 없으면 무제한(∞)입니다. `once`가 있으면 1회 오답 시 실패입니다.
- `reveal`: 실패 결과 화면에 보여 줄 정답 문구입니다. 유일하게 평문으로 두는 곳입니다.

## 미션 종류 (`kind`)
| kind | 쓰는 곳 | 필드 | 판정 |
|---|---|---|---|
| `answer` | 수리·암호·눈치·두뇌·지식 등 입력형 | `html`(문제), `placeholder`, `hash`(문자열 또는 배열), `numeric`, `once`, `reveal` | 입력을 `norm`(소문자, 공백·`%.,!?'"~·` 제거) 처리. `numeric`이면 첫 숫자 덩어리만 사용. 해시가 일치하면 성공. 시간 종료 시 입력해 둔 답이 있으면 그 답으로 판정 |
| `typing` | 타자 | `text`, `once` | 똑같이 치면 즉시 성공. `once`면 제출(Enter) 시 틀리면 실패. 붙여넣기 금지 |
| `order` | 순서 | `html`, `items`(보기, 섞인 순서), `hash` = `hash.mjs s90-order 정답1 정답2 …` | 1회 제출 |
| `chosung` | 초성 게임 | `chosung`, `words`(평문 목록), `dict` | 1회 제출, 목록에 있으면 성공 |
| `board` | 글자판 단어 만들기 (1단계 보스) | `board`(25칸), `len`, `need`, `words` | 틀려도 다시 낼 수 있음. 서로 다른 단어 `need`개 |
| `roulette` | 행운 1 | `slices: {win, lose}` | 직접 돌림 |
| `dice` | 행운 2 | `pick` | 숫자 `pick`개를 고른 뒤 주사위 1개 |
| `coin` | 행운 3 | `flips`, `need` | 앞·뒤 예측 후 던짐, `need`번 이상 맞히면 성공 |
| `baskin` | 반응 2 (베스킨라빈스 31) | `turnTime`, `lose` | 캡틴 선공, 고정 알고리즘(닿을 수 있으면 5의 배수까지, 아니면 1개). 플레이어가 5의 배수로 끝내면 반드시 이김 |
| `endword` | 반응 3 (앞말로 끝내기) | `rounds: [{word, words}]`, `dict` | 캡틴 단어 하나를 무작위로 뽑음(리얼리티 스톤 미리 보기와 같은 단어). 그 첫 글자로 끝나는 단어면 성공. 틀리면 시간 안에 다시 |
| `hanoi` | 2단계 보스 (한글 하노이탑) | `theme`, `lens`(블럭별 글자 수), `start`, `goal`, `words`, `example` | 옮길 때마다 주제 단어 입력. 글자 수·목록·중복·크기 규칙을 검사 |
| `equation` | 3단계 보스 (퍼즐 수식완성) | `target`, `image`, `numbers`, `reveal`, `example{image,target,numbers,answer}` | 안전한 자체 파서로 계산(eval 없음). `numbers`가 있으면 각 숫자를 정확히 한 번씩 써야 함. 계산 키패드 제공 |

새 형식이 필요하면 `s90.js`에서 다음을 함께 추가합니다.
- `SCREENS.play`의 `case`
- `PLAY.<kind>(t, m)`
- `preview()`: 리얼리티 스톤 미리 보기용
- 필요하면 결과 화면의 `reveal` 분기

기존 형식을 최대한 재사용합니다. 무작위 요소는 `rand(n)`(crypto)를 씁니다. 리얼리티 스톤 미리 보기와 실제 도전이 같아야 하면 `S.cur.pick`에 고정합니다(`endword` 참고).

## 정답과 단어 목록
- 해시: `node tools/hash.mjs s90 정답 별칭1 별칭2` → `hash: ['…', '…']`. 순서형은 `node tools/hash.mjs s90-order A B C D`.
- 별칭은 넉넉히 받습니다. 예: 수요일/수/수욜, 풍자/풍자법, 인공지능/ai/에이아이. 숫자 답은 `numeric: true`로 단위를 붙여도 정답 처리합니다.
- 사용자가 "이것만 정답"이라고 하면 그것만 받습니다. 예: 2단계 암호는 '스테이지구십'만 정답이고, 띄어쓰기는 무시합니다.
- 단어형 (macOS만 가능):
  ```bash
  python3 tools/kodict.py                         # 한 번만. tools/cache/ko_titles.txt 생성 (271,585 표제어, 커밋 금지)
  python3 tools/words.py chosung ㅍㄹㅈ             # 초성 일치 단어
  python3 tools/words.py board <25글자> --len 3     # 글자판 조합
  python3 tools/words.py ends 우산 무지개 소나기     # 앞말로 끝내기
  python3 tools/words.py has 프리즘                 # 표제어 여부
  ```
  - 출력된 배열을 `stageN.js`에 붙여 넣고, `dict: '뉴에이스 국어사전'`과 규칙 칩 `'뉴에이스 국어사전 기준'`을 넣습니다.
  - 3단계 `endword` 목록은 공백이 든 표제어(타나 호 등)를 뺀 버전으로 만들었습니다. 지금 `words.py`는 공백을 지우고 포함하므로 수가 조금 더 많습니다.
- 주제형 목록(국가 등)은 사전 대신 직접 만듭니다. 예: 2단계 `COUNTRIES`는 외교부 표기 + 흔한 별칭이고, 옛 왕조 이름(조선)은 뺐습니다.

## 새 단계 만들기
1. **이미지 읽기**: 사용자가 준 폴더나 zip(`KakaoTalk_Photo_… 001~030.png`)의 카드를 **모두** 봅니다.
   - 구성은 대개 미션마다 "제목 카드 → 규칙 카드(Lv, 제한 시간, 1회 오답/제출 조건, 검색 허용 등) → 문제 카드" 순서이고, 그 뒤에 보스 카드들과 "보스 성공 보상" 카드가 옵니다.
   - 채팅에 첨부되지 않은 장이 있으면 폴더에서 직접 읽습니다.
2. **정리**: 미션별로 형식, 제한 시간, 실패 조건, 문제, 정답 후보를 표로 정리합니다.
   - 사용자 메시지의 특이 사항이 우선입니다. 예: "행운은 직접 구현", "반응은 알고리즘으로 대응", "첫 이미지는 예시이니 시작 전 설명으로".
3. **정답 풀기**:
   - 계산·규칙 문제는 직접 풀고 다른 규칙으로도 맞는지 교차 확인합니다. 예: 3단계 암호는 모음 수입니다(Cat 1, Money 2, Baseball 3).
   - 사실 문제는 웹 검색으로 확인합니다. 출처마다 다르면 보고합니다.
   - 끝내 확정하지 못하면 판정을 약하게 하고 보고합니다.
4. **구현**: `s90/stageN.js`를 작성하고(`stage3.js`가 가장 최근 예시) `index.html`에 script 태그를 추가합니다(s90.js보다 앞).
   - 필요한 새 `kind`와 보상 스톤 효과를 `s90.js`에 구현합니다.
   - 보스 예시 이미지나 설명은 브리핑의 `example` 블록으로 보여 줍니다(2단계 하노이 예시, 3단계 수식 예시 참고).
5. **브라우저 검증**: 아래 디버그 스니펫으로 10개 미션 각각에 정답과 오답을 넣어 봅니다. 새 아이템 효과와 휴대폰 폭도 확인합니다.
6. **배포·보고**: `CLAUDE.md`의 배포 절차를 따른 뒤 사용자에게 보고합니다.
   - 미션별 정답, 제가 정한 해석과 값, 확인하지 못한 것을 적습니다.
   - 사용자가 정답을 정정하면 해시와 `reveal`만 바꿔 다시 배포합니다.

## 디버그 (`s90/index.html#debug`)
`window.__s90 = { S, STAGES, go, end, judge, hash, norm, resume, fresh }`. `S`는 살아 있는 상태 객체입니다.
```js
const w = ms => new Promise(r => setTimeout(r, ms));
const bak = localStorage.getItem('s90-save-v1');            // 끝나면 되돌릴 것
async function setup(stage, type, items = {}) {
  __s90.fresh(); const S = __s90.S; S.stage = stage; S.phase = 'missions';
  S.order = ['행운','수리','타자','암호','눈치','두뇌','반응','순서','지식'];
  S.idx = type === '보스' ? 9 : S.order.indexOf(type);
  S.weeks = { [stage]: { results: {}, passes: 0, hp: [] } };
  S.order.slice(0, S.idx).forEach(t => S.weeks[stage].results[t] = { r: 'success', delta: 1 });
  Object.assign(S.items, items); __s90.go('brief'); await w(200);
}
async function start() { document.querySelector('#bgo').click(); await w(3200); }   // 3·2·1 대기
// 예: await setup(3, '수리'); await start(); ans.value = '수요일'; af.requestSubmit(); → .word 가 SUCCESS
// 끝: bak === null ? localStorage.removeItem('s90-save-v1') : localStorage.setItem('s90-save-v1', bak)
```
- 미션이 진행 중일 때 새로고침하면 그 미션은 실패로 기록됩니다. 테스트 후에는 다른 페이지로 이동한 다음 저장을 지웁니다.

## 단계별 구현 메모
- **1단계**
  - 행운: 룰렛 7:1.
  - 반응: 초성 ㅍㄹㅈ, 21단어.
  - 순서: 2026 아시안게임 종목별로 걸린 메달(세부 종목) 수.
  - 보스: 5×5 글자판에서 3글자 단어 2개. 보상은 스페이스 스톤.
- **2단계**
  - 행운: 주사위 5개 고르기.
  - 암호: '스테이지구십'만 정답.
  - 반응: 베스킨라빈스 31.
  - 보스: 한글 하노이탑. 주제 국가, 블럭 1·2·3 = 2·3·4글자, 가운데 봉 → 3번째 봉, 90초.
    - 블럭별 글자 수는 에이전트가 정한 값입니다.
    - 브리핑에 '과일' 주제 7수 풀이 예시와 "안 옮겨지는 경우" 목록이 있습니다.
  - 보상: 마인드 스톤.
- **3단계**
  - 행운: 동전 4번, 2번 이상 맞히면 성공.
  - 타자: 1회 오답 시 실패(제출형).
  - 반응: 앞말로 끝내기. 캡틴 단어 5개(우산·무지개·소나기·고구마·수박) 중 무작위, 5초, 재시도 가능.
  - 순서: **사용자 정답**은 일본→베트남→미국→태국입니다. 관광공사 통계는 태국이 미국보다 앞서지만 사용자 정답을 따랐습니다.
  - 보스: 흩어진 퍼즐 사진 속 색깔 숫자로 3 만들기.
    - 빨강 14 · 청록 27 · 보라 7 · 검정 9, 사용자 정답 9 − (27 − 14 − 7).
    - 예시 이미지(27 = (13 + 5 − 9) × 3)는 브리핑에서 보여 줍니다.
  - 보상: 파워 스톤.
- **4단계~**: 아직 없음. 보상은 4단계부터 순서대로 타임 → 소울 → 크로노스의 눈 → 카이사르의 달력이고, 8·9단계 보상은 미정입니다.
